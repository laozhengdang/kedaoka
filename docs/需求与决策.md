## 三、设计原则（我提的，已达成一致）

### 3.1 增长机制要分清
- 检索池变大 ≠ 变强（冲突和噪声会稀释检索）。
- 真正的增长来自 ①**结构化沉积**（同一套 schema 跨课合并）②**反馈标签**（三档、手改、判"不像兽医题"）。
- 因此 **schema 必须在写代码前定死**，否则后面每加一门课只是多一个文件夹。

### 3.2 存储分层
```
L1 素材层   原始 PDF / 页级切片 / 原图 / 页码锚点     ← 不可变，唯一溯源锚点
L2 课程库   每门课：术语 / 机制链 / 考点 / 图卡        ← 人一版、机器一版
L3 规范层   兽医术语规范、机制模板、辨析清单、出题规范  ← 客观，有版本号，可审核
P  个人档案 三档历史、错因类型、掌握度曲线              ← 主观，私有
```
L3 与 P 物理分离。清空 P 不应影响 L3；分享/导出永远不包含 P。
（注意：按 D1/D2，L3 也不对外分享——它是每台机器自己长出来的，只是它与 P 属于两种不同性质的成长。）

### 3.3 数据格式惯例
- 每条事实都要带：值、来源、来源等级、时间、版本、provenance（`ai` / `human` / `seed`）。
- 冲突**不覆盖，只并列**；只有 S 级来源可以覆盖，其他一律进"待人工仲裁"队列。

### 3.4 防跑偏（原文称"自我强化偏差"，本项目里最危险的一条）
- **校正锚点必须是 L1 课件原文，不是 AI 上一轮的产物。** 否则错误会被第 2、3、4 次反复固化。
- 联网校正只能提高"覆盖度"和"共识度"，**不能提供真值**，所以它的角色是**交叉校验**，不是裁判。
- D4 的落地必须遵循"三源分级 + 冲突并列"，细则见 §4。

### 3.5 课件口径 vs 学理口径
- 课件是**考试标准**，学术文献是**学理标准**，两者冲突时**并存并标注**，绝不互相覆盖。
- 出题默认走考试口径；"科普/深挖"类输出走学理口径。

### 3.6 过拟合防护
- P 层只调**顺序与呈现**，不调**覆盖面**：新术语永远有不被压低的基础曝光。
- 越"懂你"越容易跳过你没考过的内容，这是明确要防的。

### 3.7 成本与离线
- 联网校正花钱，所以**分层抽样 + 结果缓存带时间戳**：核心术语全查，长尾抽样，缓存期内不重复查。
- 断网时必须能降级运行（复习不受影响）。

### 3.8 三条线：什么东西可以流向别人

"我积累的东西怎么分享出去"这个问题，必须先切成三份，因为它们的合规性、载体、更新方式完全不同：

| 线 | 内容 | 载体 | 可否分享 | 更新方式 |
|---|---|---|---|---|
| **工程线** | 解析管线怎么跑、着色/着重号怎么判、哪些页要 VLM、PDF 的坑 | **代码**（开源仓库） | ✅ 天然共享，这就是开源的意义 | git 提交 |
| **学科先验线** | 兽医术语规范、机制描述模板、辨析清单、出题规范、命名/单位惯例 | **种子包**（版本化 JSON） | ⚠️ 默认**不发布**（D7 的修订）；随开源的只有"通用教学法"那一层 | 自己发新版，或自己悄悄加 |
| **课程数据线** | 某门课的具体术语、考点、图卡、错题 | **个人库**（L2/L3 里的课程层） | ❌ 绝不 | 只在本机生长 |

**为什么课程数据不能进提示词**（技术理由，不是道德理由）：
1. 提示词不是数据库：塞进去会挤占上下文、让检索变差、而且无法溯源、无法回滚、无法版本化。
2. 它恰好破坏了 D2 最怕的事——**课程隔离**。一个塞满免疫第三章的提示词，去处理药理课件时就是污染源，出题会串味。
3. 长提示词会稀释约束：规则越多，模型越容易丢掉其中几条（context rot）。

**为什么"不公平"这个担心其实不成立**：
- 同班同老师：他喂同一份课件，得到的就是同一份库。你并没有"先训练"出什么他拿不到的东西。
- 不同老师：你的库对他**有害**——他考的是他老师的卷子，用你的重点清单复习等于背错书。
- 你真正领先的是**踩坑经验**，而它属于工程线，已经随代码开源了。

**种子包必须有合并规则**（这是现在就必须定的，影响 schema）：
- 种子条目写入时标 `origin=seed`；用户改过的标 `origin=human`。
- 新版种子包只**新增**条目，**不覆盖** `origin=human`，也不覆盖用户已长出的内容。
- 冲突时并列保留 + 提示"种子包有一条更新"，由用户决定是否接受。
- 每个人的种子包版本号可见，这就是"同一起跑线"的可验证形式。

**如果还是想把某样东西手动给同学**：走"导出单张术语卡 / 单选条目"的显式分享，由对方主动挑选导入，而不是整库灌入。这样既能帮到人，也不会污染对方的库。

### 3.9 专业模式：隔离要写在数据里，不能靠提示词自律

目标：兽医 / 动物科学 / 草业（以及以后任何专业）各是一个模式，切换后进入**完全空白、无污染**的环境，只用该模式的提示词和该模式的库。

**层级结构**：
```
Profession（兽医 / 动物科学 / 草业 …）
  └─ Course（免疫学 / 药理学 / 病理学 …）      ← 原有的"一门课一个库"
       └─ Chapter / 卡片
```
检索**只在叶子内**进行，向上只能汇总到同一 Profession 内。跨 Profession 默认**没有任何连通**。

**"污染"的真实来源（比提示词更难清，必须逐个处理）**：

| 污染源 | 为什么危险 | 处理方式 |
|---|---|---|
| 会话上下文 | 刚聊完兽医，切换到草业，模型还在"兽医语感"里 | 切换模式 = 新会话 / 显式清空上下文 |
| 全局术语表 | 你之前定的"跨课术语表"如果跨专业合并，就破坏了隔离 | 术语表也按 Profession 分区 |
| 个人档案 P | 兽医的薄弱点会影响草业的推荐排序 | P 按 Profession 分区（见待定问题） |
| 示例 / few-shot | 提示词里带兽医例子，等于悄悄注入 | 每个模式只允许引用自己 Profession 的示例 |
| 检索索引 | 一个大索引里混入别的专业的条目 | 索引按 Profession 分，物理分开 |

**提示词必须由配置组装，不能硬编码**：`base（通用教学法） + profession 先验 + course 偏好`。切换时整组替换，不允许"残留叠加"——否则切换三次以后，谁也说不清现在加载了什么。

**自检（这个必须写成自动测试）**：
- 兽医模式下问草业的术语 → 必须回答"当前模式无此库"，而不是硬答。
- 草业模式下检索 → 命中任何兽医条目即为失败。
- 新模式第一次入库 → 必须能从零冷启动，不依赖任何已有种子。

**一个好消息**：工程经验（着色判定、着重号检测、哪些页要 VLM、图注解析）是**学科无关**的。所以新专业零种子也能立刻有八成能力，缺的只是学科先验。这意味着"加专业"的成本主要在先验，不在管线。

**范围控制**：Architecture 上留出 Profession 维度（现在必须做，因为影响 ID 和路径 schema），但**只实现兽医模式的先验**；其他专业"能跑、无先验"，等真有人用再补。

**按 D10 的简化结论**：绝大多数用户只用一个专业，所以不需要"运行时切换模式"这一套复杂机制。真正要保留的只有两件事——① 数据里带 profession 字段 ② 检索时无条件带 profession 过滤。模式选择放在**首次引导**里选一次，之后藏在设置里。成本几乎为零，但以后你自己要用双专业、或者有人想换专业时，不用迁数据。

### 3.10 发布版种子包 v1 目录（通用教学法 + 兽医基础先验）

因为同学全是兽医（D7 三次修订），种子包要写得扎实。**这不是课程数据，不违反"课程库私有"的原则。**

**A. 通用教学法（学科无关，约 6 条）**
1. 重点判定的优先级：章末考点清单 > 着色/着重号 > 标题层级 > 词频
2. 释义来源顺序：课件原文 > 课件其他页 > 权威源联网补
3. 防编造：生成的释义不许超出课件所述范围，超出部分必须显式标注"（课件未述，来自 X 来源）"
4. 三档自评的语义与排程规则
5. 出题基本约束（干扰项必须真实存在、不得瞎编）
6. 卡片质量红线（一个词条一个考点，不许一卡多问）

**B. 兽医基础先验（六组）**
1. **术语四件套**：中文名 / 英文名 / 拉丁名 / 常用缩写；病名与病变名要区分（"猪瘟"是病，"猪瘟的出血性病变"是病变）
2. **物种特异性**：牛、犬、兔、禽、猪的同一病变表现不同，不能混用；药物剂量与物种绑定
3. **机制模板**：
   - 免疫：抗原提呈 → T/B 细胞活化 → 克隆扩增 → 效应 → 记忆
   - 药理：药物 → 靶点/受体 → 通路 → 效应 → 不良反应/禁忌
   - 病理：病因 → 发病机制 → 形态学变化 → 结局/转归
4. **易错辨析入库**（举例）：肉芽组织 vs 肉芽肿、血栓 vs 栓塞、充血/出血/缺血、超敏反应 I–IV 型、抗生素 vs 抗菌药
5. **出题规范**：机制题按步骤顺序给分；数字必须带单位；物种写错即错；单选四选一，干扰项取自同类的真实存在项
6. **禁忌**：不把人医结论直接套到兽医；不把网络百科当权威；不同教材分类有分歧时并列保留

**C. 课件信号（来自 415 页调研，直接可写死成规则）**
- 红字 `#FF0000` = 核心术语；深蓝 `#003399` = 标题；蓝 `#0000FF` = 次重点；深绿 `#006633` = 术语
- 着重号 = Wingdings `\uf09f` + 红色，可精确定位到被强调的词
- 药理里的 `\uf06c` 是**项目符号**，不是强调——必须排除
- 加粗无信息量（药理/病理整份都是粗体）
- 章末"本章要点/重点/思考题"优先；病理两份没有，走"无则退"路径

**D. 明确不给的东西**
- 任何一门课的具体术语表、考点、图卡（那是你的库，也是你的领先）

### 3.11 P 层拆成两半：到底拆什么、影响面在哪

现在我把 P 层当成一个"个人档案"。拆，是指把它分成**两个独立存储单元**：

**P-1 学习偏好（Learner Profile）**
- 装什么：每天刷多少张卡、图/文配比、复习时段、每张卡停留多久、要不要连续刷、提醒方式
- 从哪来：首次引导给**全局默认值**（10 张/天、图文混排文字偏多、晚上固定时段），之后你手动改 + 系统观察行为给建议
- 作用域：**跨专业共享**。换专业不用重新设置
- 规则：宽松，随时改，改错只影响舒服程度
- 清空后果：只是恢复默认，学业数据不丢
- 位置：一个与专业无关的独立文件

**P-2 学情状态（Knowledge State）**
- 装什么：每个术语的掌握度、三档历史、错因类型（记混 / 记不住 / 机制顺序错 / 图文对不上）、连续模糊次数（leech）、上次/下次复习时间
- 从哪来：纯自动，由答题行为产生
- 作用域：**必须绑定课程**（"哪个词薄弱"天然是课程相关的）
- 规则：严格，是算法输出，不随便手改（但支持"重置这张卡"）
- 清空后果：学习进度全丢
- 位置：跟课程库绑定，或按 profession/course 分区

**拆的利益（影响面逐条）**

| 影响面 | 不拆会怎样 | 拆了会怎样 |
|---|---|---|
| 换专业 | "每天10张"和"兽医薄弱点"绑在一起，要么整包丢要么整包带 | P-1 留着，P-2 按专业分开 |
| 调排程 | 排程器同时吃"偏好"和"学情"，出错时分不清是设置问题还是算法问题 | 排程器只读 P-2，P-1 只提供卡数上限 |
| 重置 | 想"重新学这门课"得写"部分清空"，最容易出 bug | 清 P-2 就完事，P-1 不动 |
| 分享/备份 | P 里有隐私，整包不敢导 | P-1 可随设置一起导出，P-2 永不外流 |
| 改默认值 | 默认值散落在每门课里，改成 12 张要遍历所有课程 | 改一处即可 |
| 以后的迁移成本 | 拆的时候要遍历全部学习记录改 schema | 现在拆 = 多写一个对象，近似零成本 |

**我的判断：拆，而且现在就拆。** 理由不是"以后可能换专业"（你说得对，多数人不会），而是**"重置"和"改默认值"这两件日常操作**——不拆这两个功能写起来别扭、用起来容易误删。

**图文比例要用配额，不能用概率**：如果只是"70% 概率出文字卡"，某天可能全抽到图卡，所谓"文字偏多"就不成立。正确做法是每天固定配额（比如新卡 10 张里 7 文 3 图），再在配额内按到期顺序排。

### 3.12 课程隔离的具体机制（D11）

专业隔离是形式，**课程隔离才是每天真正在防串味的那道墙**。

1. **物理分开**：每门课一个目录 / 一个独立索引，不是一个大库加个字段。
2. **每张卡带 `course_id` + `profession_id`**，任何查询都必须带课程过滤，无条件、不可省略。
3. **检索**：默认只在当前课程内检索。跨课检索必须显式打开，且结果要标明来源课程。
4. **出题**：一道题只能从**单一课程**抽卡，**干扰项也必须来自同一课程**——这是最容易漏的一条，免疫和病理同属兽医，干扰项一混进来，题就没法看了。
5. **模拟卷**：可以跨课组卷，但每道题必须标注来源课程，成绩按课分别统计，不混算。
6. **同名术语**：各课分区存，跨课只提供**只读对照视图**，禁止自动合并（这是 D1 时代就定下的多版本溯源）。
7. **自检**：任意一道题都必须能溯源到唯一课程；检索结果里出现非本课程条目 = 测试失败。

## 四、D4 "联网自我校正"的落地细则

### 4.1 来源分级
| 等级 | 什么算 | 能做什么 |
|---|---|---|
| S | 规划教材、兽医大辞典、官方教材、学会指南 | 可以覆盖 / 判为权威 |
| A | 同行评议论文、行业标准 | 可并列，高权重提示 |
| B | 教学网站、其他学校课件、百科 | 只提示差异 |
| C | 论坛、博客、问答 | 只记录，不进主值 |

### 4.2 校正触发点（只在入库阶段）
1. 与 L3 同名词条比对 → 差异过大则标记。
2. 与 S 级来源抽检 → 结论不一致则并列 + 报警。
3. 与 L1 原文一致性检查 → 生成的释义是否超出了课件所说的范围（防"编"）。

### 4.3 必须承认的边界
- 网上"共识"经常是二手内容互相抄，**共识 ≠ 正确**。
- 有些知识点本身在兽医界就没有唯一答案（如某些病的分类），此时正确做法是**保留分歧**，而不是选一个"看起来最权威的"。
- 校正会花钱；所以它必须可关闭、可限量（预算上限写死在配置里）。

## 九、缺口分析（2026-10-17，待你逐条裁决）

结论先说：**现在不缺功能，缺三样东西——引擎、闭环、保险。** 功能可以边做边加，这三样缺了以后补的代价是重写。

### 9.1 引擎：入库管线本身还没有设计（最致命的空白）

目前只有探针（量了 415 页），**没有"一份 PDF 进来之后到底怎么变成卡片"的设计**。这里有五个必须先回答的问题：

| # | 未决问题 | 为什么现在必须想 |
|---|---|---|
| E1 | **章节怎么切**：一份 PDF 可能是整章（免疫第 3 章），也可能含多章（药理一份 142 页里有多个系统） | 切错 → 一门课变成乱库，以后所有统计和排程都错 |
| E2 | **术语粒度**：什么算"一个名词"？"抗原提呈"算一个，还是"抗原提呈细胞"单独算？机制名算不算术语？ | 粒度定了才能去重、才能算"新卡 10 张"，否则每天张数不可控 |
| E3 | **去重与合并**：同一个术语在 8 页出现 12 次，算一张卡还是十二张？ | 决定库的体积和每日卡数 |
| E4 | **幂等**：同一份 PDF 手滑导入两次怎么办？ | 不幂等 = 库里立刻双份，且难以清理 |
| E5 | **失败重跑**：142 页跑到第 90 页 API 断了，怎么续？ | 没有断点续跑，长课件基本跑不完 |

### 9.2 闭环：现在是单向的，不是闭环

现在的链路是 `入库 → 复习`，缺三处回流：

| # | 缺口 | 说明 |
|---|---|---|
| C1 | **人工审核环节** | AI 认定的"重点"必须先给你过一遍再进库。没有这一步，错误直接进库，而且会随"成长"被反复固化 |
| C2 | **模拟卷结果回流** | 做错的题要能一键转成卡片进排程，否则模拟卷是一次性消耗品 |
| C3 | **反复错的卡自动变形** | 一张卡错了三次，说明不是记忆问题而是卡片本身有问题（太抽象/一卡多问/图不对），应自动拆卡或换图，而不是一直重推 |

### 9.3 保险：四件容易忽略但会翻车的事

| # | 缺口 | 后果 |
|---|---|---|
| S1 | **成本预估**：一次入库调多少次 API、多少钱、失败怎么重试 | 同学跑一次课件的钱可能超出预期，直接被骂 |
| S2 | **API key 管理**：存在哪、怎么加密、换 key 怎么处理 | 明文存 key 是明确的安全事故 |
| S3 | **备份与多设备**：一门课一个库，误删/换电脑/两台机器怎么办 | 数据只有一份且全在本地 = 迟早丢 |
| S4 | **课件外发合规**：老师的 PPT 上传到第三方 API 是否合适 | 这是真实问题。要么本地模型，要么给用户明确提示 |

### 9.4 功能缺口（不是架构级，但用户会立刻要）

| # | 缺口 | 优先级 |
|---|---|---|
| F1 | **检索/速查**："我想查个词" ≠ 复习。考前临时查不到是很烦的 | 高 |
| F2 | **考前突击模式 + 考试倒计时**：按天排程在期末会崩，需要"还有 14 天，按章过一遍" | 高 |
| F3 | **客观检验**：三档是自评，人有"我好像会了"的偏差。建议只对"模糊两次以上"的卡强制出一道选择/排序题 | 高 |

功能一多，"不做什么"比"做什么"更重要。目前只有 5 条（见 §五），需要随功能扩张继续补。

## 十、第三轮决策（10-17 晚）：缺口逐条裁决

### 10.1 章节切分（回应 E1）

- **D14｜一份 PPT = 一章。** 这是硬边界，不靠内容猜。药理总论（药动 + 药效）单独算一个"大章"。
  依据："给你发的一张 PPT，那就是一章的内容"。
- **D15｜PPT 内的小节由 AI 提议重排，但卡片不依赖小节。**
  - 小节切分：有标题用标题，无标题按字号/空白页/主题漂移聚类。
  - 顺序可人工拖拽调整，可回滚。
  - **关键**：卡片只锚定"页码 + 原文片段"，小节只是显示与学习顺序的视图。AI 排错了改视图即可，不迁数据。

### 10.2 术语粒度（回应 E2）

- **D16｜术语必须有 `type` 字段**：`实体`（细胞/器官/物质）、`过程`（机制步骤/生理过程）、`疾病`、`病变`、`属性`（数值/单位/分类）。
  - 典型反例：**抗原提呈（过程）≠ 抗原提呈细胞（实体）**。类型不同，卡片形态也不同（实体→名词卡；过程→机制卡）。
  - 判断依据：着色/加粗/标黄等强调字体 + 语言形态（"…细胞/…因子"多为实体；"…作用/…过程/提呈"多为过程）。
  - **硬约束**：这两个概念绝不允许被合并成一条，必须作为两条并存的卡，且互相引用（前置关系）。

### 10.3 去重与星级（回应 E3）

- **D17｜同一术语在同一章内只出一张卡**，出现多次记录为"命中次数"，不重复成卡。
- **星级公式**（重要度，1–5 星）：
  1. **真题/题库命中**（最高权重，你说"题肯定是最优先的"）
  2. 是否出现在章末要点/思考题
  3. **跨页出现频率**（⚠️ 不是"同一页内重复次数"——页内重复多半是排版）
  4. 着色等级：红 > 蓝 > 深绿 > 深蓝标题；着重号额外加权
  5. 加粗（只在整份文档加粗不普及时才有信息量）
- **D18｜星级影响抽卡频率与复习密度，但低星卡必须保底低频出现。** 否则考试考边角料就完了（对应 §3.6 过拟合防护）。

### 10.4 四档自评（新）

- **D19｜四档**：①记得且以后不用再考 ②记得，不用看概念 ③模糊，要看概念 ④完全不记得。
- ⚠️ **"以后不用再考"必须做成"毕业"而不是"删除"**：
  - 从**日常队列**移除，减轻负担；
  - 但仍进入**考前抽检池**，突击模式下会被抽到；
  - 30 天后自动回归抽检一次，防止"当时以为记住了"。
  - 理由：一次自评就永久移除，是遗忘曲线最经典的陷阱。

### 10.5 幂等与重复导入（回应 E4）

- **D20｜不靠 AI 判重，靠指纹**：
  1. 文件级 `sha256` → 完全相同，秒判，直接提示"这份已导入"。
  2. 页级 hash → 部分页相同，列出差异页。
  3. 文本相似度 75%–95% 的灰区，才用 AI 判定"是不是同一份的修改版"。
  4. **不自动删除**，进"重复批次"待你确认——自动清除的风险远大于收益。
- 依据：你说"让 AI 审核一遍"，方向对，但 AI 在这一步是**最低效、最不可靠**的一档，前两级能在 1 毫秒内解决 95% 的情况。

### 10.6 断点续跑（回应 E5）

- **D21｜页级任务队列 + 幂等键 + 追加 journal**：
  - 任务键 = `file_hash + page_no + stage`，天然幂等，重复跑不会重复计费。

### 11.2 断点续跑：调研结论与最终组合（修订 D21）

调研了业界做法（单机桌面端，不需要分布式那一套），可组合的方法有五条：

| 方法 | 出处/思路 | 本项目的用法 |
|---|---|---|
| **文档指纹表** | LlamaIndex 的 docstore 用 `doc_id → document_hash`，哈希没变就跳过、变了才重跑 | 建一张 `file_hash / page_hash → 已处理` 表，重跑时先查表 |
| **检查点（checkpoint）** | LangGraph 的 checkpointer / 持久化，每步落状态，崩了从最后一步恢复 | 每页每阶段落一条 journal（对 D21 的补充，二者是一回事的两个名字） |
| **内容寻址缓存（CAS）** | 以"请求内容的哈希"为键缓存结果 | 同样的 prompt+原文 → 直接命中缓存，**重跑不重复计费** |
| **单机任务队列** | SQLite 当队列（`simonw/absurd-in-sqlite` 之类），单写入线程 + WAL | 桌面端正好；进程被任务管理器杀掉也能恢复 |
| **死信队列 + 指数退避** | 失败页进 DLQ，隔 5s/30s/2min 重试，超次数标记"需人工" | 防止某个坏页把整批卡死 |

**最终组合（D35）**：`页级任务表（SQLite） + file/page hash 跳过 + 每步 journal + CAS 响应缓存 + DLQ 重试`，再加**两段式**（本地段不联网先跑完，AI 段分批）。这样最坏情况丢的是"正在跑的那一页"，最多重跑 1 页。

参考资料：
- LlamaIndex 文档管理/去重：<https://developers.llamaindex.ai/python/examples/ingestion/document_management_pipeline/>
- LangGraph 持久化与检查点：<https://docs.langchain.com/oss/python/langgraph/persistence>
- Thoughtworks 雷达把"忽略 agent 工作流的持久性"列为反模式：<https://www.thoughtworks.com/zh-cn/radar/techniques/ignoring-durability-in-agent-workflows>
- SQLite 当队列的实践：<https://github.com/simonw/research/blob/main/absurd-in-sqlite/absurd_sqlite.py>

## 十二、第五轮决策（10-18）

### 12.1 断点续跑："全上"是对的，但必须合成一个机制（D44）

你的直觉对：五条都要有。但**不是五个系统并排放**——那是五个账本，会互相打架。正确做法是：

```
tasks 表（唯一真相源）
  id, file_hash, page_no, stage, status, retry_count, result_path, updated_at
cache 表（只省钱，不管进度）
  request_hash, response, model, ts
```

- **hash 跳过** = tasks 表上的一个字段，不是独立系统
- **checkpoint / journal** = tasks 表的 `status`，加上结果文件**原子写**（写临时文件 → rename，防断电留半个 JSON）
- **DLQ** = tasks 表里 `status='failed' AND retry_count>=3`
- **CAS 缓存** = 第二张表，独立，只负责"同样请求不重复计费"
- **SQLite + WAL + 单写入线程**，避免并发写坏

**如果真做成五套独立机制，会出现这三种 bug**（这就是为什么不能"各管各的"）：
1. 哈希表说"处理过"，journal 说"没完成" —— 信谁？
2. 缓存命中，但任务表状态没更新 —— 下次又重跑一遍（白省钱）
3. 死信队列里的条目在任务表里已经不存在 —— 幽灵任务，重试到不存在的页

**一句话规则：进度只有一个账本（tasks 表），其他都只是它的属性或旁路。**

### 12.2 卡片纠错按钮（D45）

- 卡片右上角两个小按钮：**「释义有误」**、**「图配错」**。不按 = 不评价（**不是"正确"**）。
- 按下之后必须做三件事：
  1. 立刻从排程队列移除（避免继续学错）
  2. 进"待修队列"，你可以改，也可以不修、永久标坏
  3. 记录错误类型，用于校准：哪类卡、哪个来源容易错 → 以后生成时重点检查
- **schema 要点**：默认值存 `null`（未评价），不要存 `correct`。否则"没看过"和"看过且对"混在一起，准确率统计全废。

### 12.3 复习中断与跨天（D46）

- 记住位置，回来从下一张继续。
- **当天队列生成一次后就固定**（存下来），关掉再开还是这一批，不会每次打开都换一批。
- **跨天未完成**：顺延成第二天的额外负载，但设**积压上限**（建议不超过 2 天量），超过就砍掉低星卡。否则雪球会越滚越大，最后你干脆不打开了。

### 12.4 平台：确认不做手机端

- D27 维持：**只做桌面端**。不做手机、不做同步。小众无所谓，目标就是给认识的同学用。
- 「导出 Anki」与手机端无关（Anki 也有桌面版），此项**待你定**，见 §七 第 11 条。

### 13.8 第六轮裁决（10-18）：三条全部采纳

- **D48｜G1 三元锚点：采纳。**
  锚点 = `file_hash + page_no + text_fingerprint`，解析时按文本指纹就近匹配，页码只作提示。
  你说"老师基本不会改版"——同意，改版不常见。但成本几乎为零（文本指纹本来就要存），而一旦撞上一次（老师补页、不同届教材、同学之间课件版本不同），没有它整库锚点同时失效。这是保险，不是功能。
- **D49｜G2 真相源：采纳 SQLite 为唯一真相源。**
  `course.db`（SQLite）是机器读取与写入的唯一来源；Markdown / JSON 是**可随时重建的导出物**，永远不反向写入。避免两套并行写导致的分叉。
- **D50｜G3 考点实体：建，并且开放"AI 自行出题"。**

### 13.9 D50 细则：考点实体 + AI 出题的红线

**实体关系**
```
knowledge_point（考点）  ← 老师想考什么
   ├─ card（名词卡 / 机制卡 / 图卡 / 对比卡 …）   ← 怎么问
   └─ question（真题 / AI 生成题 / 模拟题）        ← 具体题目
```
考点来源三选一：① 课件章末清单 ② 真题映射 ③ **AI 从权威资料归纳（需标注、需确认）**。

**AI 自行出题的七条红线**
1. **不许凭空造考点**。新题必须挂到已有考点下；确实需要新考点时，先创建并标 `origin=ai`，等用户确认。
2. **只用 S / A 级来源**（规划教材、兽医大辞典、学会指南、同行评议论文）。B 级（教学网站/百科）、C 级（论坛）**不许用来出题**（分级见 §4.1）。
3. 每道题必须记录：`origin=ai_generated`、依据来源、对应考点、生成时间。
4. **生成后进"待审队列"，默认不进复习队列。**
   —— 理由：错题会训练出错误记忆，**比没有题更糟**。这一步不能省。
5. **不得超出课件覆盖范围**（防止考纲外内容混进复习）。
6. 每题必须能回答"考的是哪个考点"；答不上来，说明这题是垃圾，丢弃。
7. **默认按需生成**（你想练某章时才生成），不自动全量生成——出题要查资料 + 推理，比抽卡贵得多。单考点生成数量设上限（如 10 题）。

**排序原则**：真题 > 老师章末题 > AI 生成题。AI 题永远排在真题后面。

## 十五、第七轮：不止 PPT，三类输入（10-18）

### 15.1 核心修正：PPT 不是"权重低"，它是"覆盖面基准"

你说"资料的权重肯定要更高，授课 PPT 的权重更低"。方向我同意，但这里要拆成**两个独立的维度**，否则会出大问题：

| 维度 | 回答什么问题 | 谁说了算 |
|---|---|---|
| **权重（source_rank）** | 这个东西**多重要** | 真题 / 复习资料 |
| **覆盖面（coverage）** | 这个知识**有没有被讲到** | 授课 PPT（唯一完整覆盖的来源） |

如果把 PPT 简单标成"低权重"，后果是：**只有真题考过的内容会被复习，PPT 里那些还没考过、但老师讲过的内容会被饿死**。而我们前面专门定过"低星保底"，就是为了防这件事。

所以规则是：**权重决定"多频繁"，覆盖面决定"有没有"**。两者相乘，才决定一张卡的排程。

**D51｜来源等级四档**

| 等级 | 什么算 | 作用 |
|---|---|---|
| **S+** | 历年真题、老师发的题库（真实考过） | 星级最高权重；直接进模拟卷题库 |
| **S** | 老师的复习资料、重点整理、考试大纲 | 星级高权重 |
| **A** | 授课 PPT | 覆盖面基准，完整覆盖全部内容 |
| **B** | 学长笔记、同学整理、网上资料 | 只做补充，必须标注来源，可随时关闭 |

### 15.2 导入不是"加个按钮"，是三条管线

**D52｜导入时选类型，三类走三条不同的解析管线：**

| 类型 | 解析目标 | 产出 |
|---|---|---|
| **授课 PPT** | 术语、机制、图、章末清单 | 卡片（挂到考点下） |
| **题库 / 真题** | 题干、选项、答案、解析、分值 | `question` 实体 + 考点映射 |
| **复习资料** | 先判断它是"知识"还是"题目"，再分流 | 卡片或题目 |

- 选择方式：**AI 预判 + 你确认**（你不能指望同学每次都手动选对）。
- 允许一个文件里混着（复习资料经常既有知识点又有题）→ 按块分流。

### 15.3 题库解析的四个现实难点

这些不定，题库导进来会是一团乱：

| # | 难点 | 处理 |
|---|---|---|
| Q1 | **答案和题目分离**（答案常集中在文末） | 先抽题，再抽答案区，按题号对齐；对不上的标"答案缺失" |
| Q2 | **题号不规整**（1. / 1、/ （1）/ 第1题） | 多模式匹配 + AI 兜底；宁可标"识别不确定"也不瞎猜 |
| Q3 | **老师给的答案也可能错** | 题目答案状态三档：`已确认` / `待确认` / `有争议`。**`待确认` 的题不进模拟卷** |
| Q4 | **重复题**（真题和模拟题里同一道） | 按题干指纹去重，保留来源列表 |

### 15.4 高权重怎么兑现（你问的两件事）

**① 复习优先**：不是"真题当卡刷"，而是**真题命中的考点升星** → 那个考点下的所有卡都排得更勤。这样真题的价值传导到了知识层，而不是只记住那道题。

**② 模拟卷**：真题直接用会退化成背答案。建议配比：

| 成分 | 占比 | 作用 |
|---|---|---|
| 真题原题 | 30% | 保证"像真考" |
| 真题变体（AI 改写选项/情境） | 40% | 防死记硬背 |
| 纯 AI 生成题 | 30% | 补覆盖空白 |

**③ 一个副产品，你可能会喜欢**：真题按考点映射完之后，能算出**"考点覆盖地图"**——哪些考点年年考、哪些考点从没考过、今年新增的考点是哪些。这基本就是老师没说出口的考纲。

### 15.5 冲突规则：以课件为准（修订）

- **D54｜真题答案与课件不一致时，统一按课件来。** 课件是考试口径，老师按自己的口径改卷。
- 但**必须留痕，不许悄悄改**：冲突记一条日志（课件说法 / 真题说法 / 时间），卡片正面不展示，只在卡片背面或设置里可查。
  - 理由：不留痕的话，你以后翻到那道真题会以为工具出错了；留痕的成本几乎为零。
- **这类题不进模拟卷**（否则你会按错答案练），但保留在题库里，标 `答案与课件不一致`。
- 延伸规则维持不变：**任何单一来源都不能单方面改写知识**——这条现在具体化为"课件是最终裁判，但所有冲突都要留证"。

## 十六、第八轮：概念层级（父子关系）（10-18）

### 16.1 需求

`受体` 是一个大概念，它的**特性**包括：特异性、敏感性、饱和性、可逆性、变异性。

- 翻开"受体"这张卡时，要**把这些子概念全部罗列出来**；
- 同时子概念也可以**单独成卡**（考试会单独考"饱和性指什么"）。

### 16.2 关键：这是三种不同的关系，不能混

| 关系类型 | 含义 | 例子 | 用错会怎样 |
|---|---|---|---|
| `prerequisite`（先修） | 不懂 A 就学不会 B | 抗原提呈 → T 细胞活化 | 排程顺序错 |
| `attribute_set` / `contains`（属性列举） | A **有哪些**子项，**无序** | 受体 → {特异性, 敏感性, 饱和性, 可逆性, 变异性} | 卡背缺内容；列举题出不出来 |
| `ordered_steps`（有序步骤） | A 的过程有**先后** | 抗原提呈 → 活化 → 扩增 | 把无序特性当步骤，生成"把受体的 5 个特性排序"这种废题 |

**D55｜关系统一进一张 `relation` 表，带 `type` 枚举**：
`prerequisite` / `contains` / `attribute_set` / `contrast`（同层辨析）/ `ordered_steps`（有序）。

### 16.3 父子一致性：父卡只存 id，不存文字（D56）

**硬约束**：父卡不"抄"子项文字，只存**子项 id 列表**；背面展示时**实时读子卡**。

理由：
- 你在子卡上改了"饱和性"的释义，父卡不会留着一个旧版本；
- "父卡列 5 条、库里只有 3 张卡"这种不一致，**根本不可能发生**。

反过来，如果父卡里直接写一段"受体的特性：特异性、敏感性…"，它和子卡就是两份真相，一定会分叉。

### 16.4 没说但必须有：列举型主动题（D57）

属性的完整列举，是**最容易失分、最容易漏复习**的地方（"受体有几个特性？"答出 3 个就扣分）。这类题**零成本生成**，因为子项集合就在库里：

> 题：受体的特性包括哪些？（提示：共 5 项）
> 答：特异性、敏感性、饱和性、可逆性、变异性

- 生成：从 `attribute_set` 直接拼装，不调 AI
- **提示条数**（"共 5 项"）是有效线索，显著提高回忆准确率
- 反向题也能出：给 4 个真特性 + 1 个干扰项（从同类型实体借），问"哪个不属于受体"

### 16.5 顺带的两个副产品

1. **同层兄弟 → 对比卡（零成本）**：特异性 vs 敏感性 vs 饱和性，天然是辨析对象。同一父节点下的兄弟可自动配对。
2. **子卡背面的上下文**：翻开"饱和性"时，背面显示「属于：受体 · 特性 3/5」。防止孤立记忆——你永远知道这块拼图在哪。

### 16.6 入库时怎么自动发现层级

**D58｜AI 提议 + 人工确认**，识别线索按可靠性排序：

| 线索 | 可靠性 | 例子 |
|---|---|---|
| 编号列表（1. 2. 3. / ①②③） | 高 | "受体的特性：①特异性 ②敏感性…" |
| 句式线索 | 中高 | "包括 / 分为 / 有以下 / 特点有 / 主要表现为" |
| 表格行 | 中 | 一行一个子项 |
| 同页并列的强调词 | 中 | 同一段里被红字标出的 5 个名词 |
| 跨页推断 | 低 | 不自动入，必须人工确认 |

准确率不会 100%，所以必须人工确认——但确认成本很低（是 / 否 / 改）。

### 16.7 一个提醒：层级 ≠ 重要

"受体有 5 个特性"是重点，不等于每个特性的**分子结构**都是重点。层级只决定**怎么组织与展示**，不决定星级。星级仍来自真题、章末清单、跨页频率、着色。

### 16.8 展示规则（数量上限）

- 默认显示前 **5** 条（按子项星级排序），其余折叠成"还有 4 项"
- 折叠**不影响**列举题——列举题永远要全部

## 十七、第九轮：交互细则与两个新功能（10-18 夜）

### 17.1 你问的那个问题，暴露了我方案里的一个错误假设

> "如果它是重点，但我选了跳过（因为我记得很清楚），那怎么办？"

根源不是"①②弹不弹窗"，而是我隐含的一个假设：**让"是否重点"依赖你每张卡手动标一次。**

这个假设是错的。**重要度是客观的（老师口径），不该靠你复习时顺手点出来。** 你的手标只是**校准 AI 的信号**，不是重要度的唯一来源。

所以三条一起解决：

1. **重要度与记忆状态解耦（D59）**：`importance`（星级，来自真题/章末清单/跨页频率/着色）由系统算；`human_importance`（你的判断）只作为**校准信号**。你选①，只改记忆状态，**不改星级**。
2. **①档不弹窗**，但系统记住"这张你跳过了"。
3. **毕业卡仍进考前抽检池**（D19）+ **结算页批量复核**：
   ```
   今天标了"不再考" 3 张
   [ 免疫应答·抗原提呈 ] [ 超敏反应分类 ] [ 补体三条途径 ]
   → 这些仍会在考前抽检。要移出抽检池吗？ [ 移出 ] [ 保留 ]
   ```
   批量、不打断、可跳过。于是"标重点"从**每张卡 1 次操作**降成**每天 0～1 次操作**。

### 17.2 设置体系（D60）

**每个功能都该能关**，但设置项一多等于没有设置。分三层，第三层默认折叠：

| 层 | 内容 | 打开频率 |
|---|---|---|
| **学习节奏** | 每日新卡数、复习卡数（默认 10 + 5，可调）、图文配额、复习时段、突击档位 | 一学期 1–2 次 |
| **显示偏好** | 周视图 开/关、总进度 开/关、连续天数 开/关、深色模式、字号、衬线/无衬线 | 装好时设一次 |
| **高级（折叠）** | API 配置、种子包版本、导出整库、重置某门课、清空学情 | 很少动 |

原则：**默认值要能用**，设置是给"有意见的人"的出口，不是必经流程。

### 17.3 API 配置引导（D61）

```
选择你的 AI 服务
  ● DeepSeek（推荐）   便宜、中文好、够用
    一般每份课件入库约 几毛钱，一学期大概 10–30 元量级
  ○ OpenAI / Kimi / 智谱   也可以，但通常更贵
    价格以各家官网为准
```

- **具体价格不写死**，只写量级 + "以官网为准"。写死就是给自己埋投诉。
- 必须接一句"同学自付"的明示（早已定过）。

### 17.4 鼠标 + 键盘双通道（D62）

**不是两套系统**，是**同一排按钮，两种触发方式**：

- 鼠标点击永远可用，这是主交互
- `1/2/3/4` 是同一动作的加速键，默认开启、可关
- 按钮上的小号数字 `1` `2` `3` `4` **只在鼠标移到该区域时淡入**，不打扰点击党

### 17.5 每日配额可调（D63）

- 默认新卡 10 / 旧卡 5，设置里可改（5+3 应对忙的时候，20+10 应对冲刺）
- **容量校验必须跟着重算**：上限调低，"突击模式每天需要多少张"要重新算
- 改了上限不影响已有排程，只影响从明天开始的取卡

### 17.6 计时器：独立工具，不是复习的附属（D66，推翻上一版）

**上一版我错了。** 我把它当成"复习会话的统计器"，所以设计了 90 秒无操作自动暂停。你说的场景把它推翻了：

> 在图书馆把电脑摆在桌上当计时器，人在翻书、在看手机，偶尔抬头看一眼数字还在动。
> **90 秒不动就暂停，等于逼人动鼠标——那才是分心。**

所以定位改成：

> **计时器是一个独立的通用小工具，跟复习、跟这个工具的其他功能都无关。**
> 你可以只翻书、只做笔记、只发呆，打开它就是为了知道"这次坐了多久"。

**规则（全部按你说的改）**：

| 项 | 决定 |
|---|---|
| 自动暂停 | ❌ **取消**。无操作、切窗口、最小化，都继续走 |
| 暂停 | 只有**手动**。吃饭/走开自己按 |
| 整点提示 | 保留，可关（"已经 1 小时了，再接再厉"） |
| 奖励/惩罚 | 没有。**工具不监督人** |
| 形态 | 窗口化 / 全屏 / **窗口置顶**（图书馆场景必备：一直浮在最前面） |
| 默认状态 | **锁定**（鼠标移上去才出现暂停键），防误触 |
| 显示 | 只有数字。不放进度环、不放鼓励语、不放统计 |

**关于"数据会不会假"**：会，而且我接受。你说得对——**学生有主动性，故意放任时间流逝，遭殃的是他自己**。这个工具不承担"监督"职责，它只负责**记录**。

**新增的两条**：
- 计时器可以**起个名字**（"看书·兽医病理学第3章"），结束时可存一条历史
- 有些场景只想要一个**纯数字窗口**，那就给它一个"极简模式"：无标题栏、无按钮，只有时间

### 17.7 考试时钟（D65）

与计时器共用组件，但**是另一个东西**（它服务于"这场模拟卷"）：

| 模式 | 用途 | 显示 |
|---|---|---|
| **正计时** | 日常复习，想做多久做多久 | `已学习 42 分` |
| **倒计时** | 模拟卷，"这套我给自己 1 小时" | `剩余 42:17`，最后 5 分钟变红 |

- 倒计时到点：**不强制交卷**（强制交卷会丢数据、会被骂），标 `超时完成`，成绩页写"超时 6 分钟"
- 最后 5 分钟提示一次（可关）
- 模拟卷页可带预设时长（如 60 分钟），点开始即进倒计时

### 17.8 数据模型：两类会话必须分开存（D67）

| 表 | 是什么 | 关联 |
|---|---|---|
| `review_session` | 复习会话（自动记录，含每张卡的结果） | 绑课程 / 卡片 |
| `timer_session` | **独立计时**（跟课程无关，可无标签） | 不绑任何东西 |

为什么不合并：合并会让"学习时长"这个数字混入两种语义——一种是"我坐了三小时但只刷了 10 张卡"，一种是"我刷了 200 张卡"。**结算页该显示的是前者，统计页该同时给两个数。**

字段草案：
- `timer_session`: `start_at, end_at, duration_sec, paused_sec, label, mode(stopwatch|countdown), limit_sec, overtime_sec`
- `review_session`: `start_at, end_at, duration_sec, cards_done, ratings{1:..,2:..,3:..,4:..}`

### 17.9 两个计时器，必须分清（D68）

上一版我把"限时"从计时器里删干净了，删过头了。正确的做法是**两个计时器并存，规则相反**：

| | ① 独立计时器 | ② 卡片计时器 |
|---|---|---|
| 是什么 | 桌面小工具 | **复习屏里的一个按钮** |
| 目的 | 知道我坐了多久 | 知道**这一张卡**想了多久 |
| 无操作 | 继续走 | **计时本身就在计"你正在想"，不需要操作** |
| 上限 | 无 | **默认 90 秒**，到点执行结束动作 |
| 形态 | 独立窗口、可置顶 | 复习屏右上角 `⏱ 0:32`，可折叠成一个数字 |
| 绑定 | 不绑任何东西 | 绑这一张卡 |
| 数据 | `timer_session` | 就是 P-2 里的 `latency_ms`，**不是新数据** |
| 开关 | 独立功能 | 设置里「卡片限时」可关 |

**卡片计时器只在"正面等你选择"的时候走。** 你按了 1–4 就停。所以它永远不会误伤——它计的就是思考时间。

**到点做什么（三选一，默认第 3 种）**：

| 选项 | 行为 |
|---|---|
| 只提醒 | 变红显示"已超时 12 秒"，等你手动选 |
| 自动翻面 | 直接显示答案，但**不替你选档** |
| **自动翻面 + 记③模糊** ← 默认 | 显示答案，同时记一张"模糊"，并标 `auto=true` |

理由：卡住超过 90 秒，继续想的收益已经很低，但也不能替你记成"不会"（你自己会不服）。记"模糊"是最接近真实的状态。

- `auto=true` 的卡在结算页单独列一行："3 张超时自动标记"——你能看到，也能改。
- 阈值 60 / 90 / 120 秒可调，也可彻底关掉。

**两个同时开会不会分心**：会。所以复习屏里，独立计时器自动**折叠成一枚小圆点**（左下角），点开才展开。想专注复习的人看不见它，想边看时间的人点一下就有。

**顺带一个免费的质量指标**：`latency_ms` 攒起来能算"某个考点的平均思考时长"。平均值明显偏高的卡，往往不是"你记性差"，而是**卡本身有问题**（太抽象、一卡多问、配图不对）。这正好给 C3「反复错的卡自动变形」多了一个判据，而且零成本。

## 十八、计算类科目的复习设计（10-19，基于真实数据实测）

> 素材：`data/source_pdfs_chem/` 里 6 份文件（无机及分析化学：绪论、分散系、热力学、平衡、动力学 + 第一章课后题答案），共 284 页。
> 探针：`_probe/chem_scan.py`、`chem_formula.py`、`chem_stats.py`。

### 18.1 实测结果：这类课件和兽医课件长得完全不一样

| 指标 | 数值 |
|---|---|
| 总页数 | 284（5 章 + 3 页答案） |
| 文字密度 | **中位 126–180 字符/页**（兽医课件大约是这个的 3–4 倍） |
| 含数学符号的页 | **142 页（50%）** |
| 含上下标的页（≈ 有公式） | **101 页（36%）** |
| 大面积图片页（>15% 面积） | 69 页（24%） |
| 例题 / 解答 | 13 页 / 23 页，成对出现 |
| **内嵌单选题** | **18 页**（老师自带的测验，带"1分""提交"字样） |
| 课后答案 | 3 页，**0 个字符**（纯图片，必须 OCR） |

⚠️ 一个假象要先戳破：探针最初显示"100% 的页含图片"，那是因为**每页都有中国农业大学的校徽**。按"图片覆盖面积 >15%"算，真正有图的只有 69 页（24%）。

### 18.2 最关键的技术发现：公式是碎文本框，不是图片

第 1 章 p25 渲染出来是一个完整、漂亮的分式：

```
x_B = n_B / (n_A + n_B) ≈ n_B / n_A = n_B / (m_A/M_A) = b_B·M_A
```

但文本层抽出来是这九个碎片：`B` `A` `B` `B` `n` `n` `n` `x` `+` `=`。

**结论三条**：
1. **不能指望文本层重建公式**——分数线一打散，语义就没了。
2. **也不能整页送 VLM**——284 页里 36–50% 涉及公式，整页视觉的成本会是兽医课件的十倍。
3. **正确做法：定位公式区域 → 裁切成小图 → 只把裁切图送 VLM 转 LaTeX → 结果缓存复用**。
   - 定位线索：`SymbolMT`/Cambria Math 字体 + 上下标 + 密集的 `draws`（分数线是矢量线）
   - 缓存键 = 裁切图的 hash。**"拉乌尔定律"这个公式全库只转一次**，之后所有出现都复用。

### 18.3 设计上最根本的区别：复习单位不是"名词"，是"题型"

| | 概念科目（免疫 / 病理） | 计算科目（无机分析化学） |
|---|---|---|
| 复习单位 | 一个名词 | **一类题** |
| 怎么判对错 | 自评（四档） | **必须判分**（输入答案） |
| 记住什么 | 释义 | 公式 + 适用条件 + 解题步骤 |
| "会了"的标准 | 说得出来 | **算得对** |

所以四档自评在这里**不够用**——"我记得这个公式"和"我会用这个公式"是两件事。四档要改语义：

| 档 | 计算科目里的含义 |
|---|---|
| ① | 秒出思路，且算对 |
| ② | 算对了，但慢/绕 |
| ③ | 算错了（或知道思路但算错） |
| ④ | 完全没思路 |

**判断"算没算对"不能靠你自己说，要靠系统判。**

### 18.4 五种新卡型

| 卡型 | 正面 | 背面 | 判分 |
|---|---|---|---|
| **公式卡** `formula` | 公式名（拉乌尔定律·质量摩尔浓度式） | 公式（LaTeX）+ 每个符号含义与单位 + **适用条件** + 常见变形 + 什么时候不能用 | 默写 |
| **题型卡** `problem_type` | 题型描述 + 一道例题 | **解题模板（步骤清单，不是答案）** + 关键判断点 | 三步自评 |
| **计算题卡** `problem` | 题目（数字可随机化） | 分步提示 → 完整解答 | **输入答案，系统判分** |
| **单位/量纲卡** `unit` | `mol·L⁻¹` ↔ `g·L⁻¹`；"某反应速率常数单位是 L²·mol⁻²·s⁻¹，几级反应？" | 换算与推导 | 选择题 |
| **适用条件卡** `when_to_use` | "ΔH 什么时候可以近似等于 ΔU？" | 条件 + 反例 | 选择题 |

**题型卡是这类科目的主力**。你课件里 p25 那句"解题要领：1. 正确分析体系经历的过程或路径；2. 找出所有涉及能量变化的状态函数；3. 正确计算"——那就是模板，直接抽出来。

### 18.5 计算题怎么判分

不是"对/错"两个字，是三重校验：

1. **数值**：相对误差 ≤ 1%（化学里有效数字决定容差）
2. **量纲**：单位必须对（`pint` 做量纲检查），单位错就判错，哪怕数值对
3. **有效数字**：位数不对给"提醒"而非判错（老师要求不同）

答错之后给的是**分步提示**，不是答案：
第一步提示（该用哪个公式）→ 第二步提示（该代入哪个量）→ 完整解答。这样一道错的题能变成三次回忆。

### 18.6 程序化出题：这是计算科目最大的杠杆

例题全都是"**模板 + 参数**"：

```
例：在 101.3 kPa, 373 K 下，水的气化热为 40.6 kJ·mol⁻¹。
    计算 1 mol 水完全气化时系统的 ΔU。
```

`Q = 40.6`、`n = 1`、`T = 373` 是参数，公式是模板。于是：

- 把模板抽出来，参数化（取值范围 + 约束）
- 每次出题随机取参数
- **答案用 sympy 算**，不是模型算

好处：无限变式、**零 AI 成本**、答案 100% 正确、防背答案。

**硬闸门（呼应"错题比没题更糟"）**：任何由 AI 生成的化学计算题，答案必须过 `sympy` 数值验算 + `pint` 量纲检查，**不通过就直接丢弃**，不做人工复核——复核也是浪费时间，因为重生成更便宜。

### 18.7 配额要按类型分开算

计算题不能按"张"算——一道题可能要 3 分钟。所以混合科目里：

> 概念/公式卡 **10 张** + 计算题 **3 道**

而不是笼统的"每天 15 张"。

### 18.8 成本警告（和兽医课件的真实差距）

| | 兽医（415 页实测） | 无机分析化学（284 页实测） |
|---|---|---|
| 需要视觉处理的页 | 3.6% | **36–50%**（涉及公式） |

差距大约 **10 倍**。压成本的全部指望在两个地方：**公式区域裁切**（不是整页）和 **LaTeX 结果缓存**（同公式复用）。

### 18.9 待你确认（影响设计）

1. **分析化学部分呢？** 这 5 章（绪论/分散系/热力学/平衡/动力学）看着像物理化学，滴定、误差、pH 计算、重量分析这些还没出现。
2. **课后题答案只有第一章 3 页**，其余章的答案有吗？没有的话，计算题的标准答案只能靠程序生成。
3. **内嵌那 18 页单选题的答案在哪？** PPT 里只看到题目和"提交"，没看到答案。
4. **考试允许用计算器吗？** 允许 → 题目可以带真实数值；不允许 → 出题要挑好算的数。
5. **有效数字要求严格吗？** 严格 → 判分要查位数；不严格 → 只看量级。

### 18.10 产品流程：同学上传一份计算类课件之后，到底发生什么

（10-19 补。微信里那份和之前分析的 5 份 PDF **sha256 完全一致**，不必重扫。）

```
① 拖入文件
② 类型预判：授课 PPT
③ 课程形态探测（纯本地，0.5 秒，不花钱）
   → "检测到 50% 页面含数学符号、36% 有上下标、13 处例题
      判为【计算型】课程，将生成公式卡 / 题型卡 / 计算题卡"
   → [ 就这样 ]  [ 改成概念型 ]
④ 预估：284 页 · 公式裁切 142 处 · 约 1.8 元 · 约 25 分钟
⑤ 入库（本地段 → 公式裁切 → VLM 转 LaTeX → 生成卡片）
⑥ 抽检 5 张（**必须含 1 道计算题**，让你验证答案对不对）
```

**形态探测不是"问用户"，是"测出来"**——同学自己也不知道这门课算哪一类。指标全部来自本地统计，零成本：

| 指标 | 概念型 | 混合型 | 计算型 |
|---|---|---|---|
| 含数学符号页占比 | < 10% | 10–30% | **> 30%** |
| 含上下标页占比 | < 5% | 5–20% | > 20% |
| 例题/解答对数 | 0 | 若干 | ≥ 5 |
| 内嵌选择题页 | 少见 | 常见 | 常见 |

实测这门无机分析化学：数学符号 50%、上下标 36%、例题 13 → 稳稳的「计算型」。
兽医专业课里更常见的是**混合型**（概念为主 + 少量计算）。

### 18.11 三种形态共用一套引擎，只换卡型权重

| | 概念型 | 混合型 | 计算型 |
|---|---|---|---|
| 主力卡型 | 术语 / 机制 / 图 | 术语 + 题型 | 公式 / 题型 / 计算题 |
| 判分方式 | 四档自评 | 混合 | 计算题必须判分 |
| 公式处理 | 不做 | 只处理公式区域 | 全量裁切 + LaTeX |
| 每日配额 | 15 张 | 10 卡 + 2 题 | 8 卡 + 4 题 |
| 一次复习预计用时 | 约 8 分钟 | 约 12 分钟 | 约 20 分钟 |

**不做两套产品**。同一套库、同一套排程，只是生成的卡型不同。这也是 `course.mode` 只是一个字段、而不是三套代码的原因。

### 18.12 兽医专业真正会遇到的"计算课"，不是物理化学

| 课程 | 真实考点 |
|---|---|
| 兽医统计 / 生物统计 | t 检验、卡方、方差分析——核心是**选对检验方法** |
| 药理学剂量换算 | mg/kg × 体重 → 总量；C₁V₁ = C₂V₂ 稀释 |
| 临床化验判读 | 单位换算、参考区间、阴阳性判断 |
| 饲料配方 / 营养 | 配比与能量计算 |

**结论：兽医的计算课，八成考点是"判断"和"套用"，不是推导。**

所以题目配比不能全是计算题：

| 题型 | 建议占比 | 例子 |
|---|---|---|
| **判断卡**（选哪个方法） | 35% | "这两组数据该用 t 检验还是卡方检验？" |
| **适用条件卡** | 20% | "ΔH ≈ ΔU 的前提是什么？" |
| **计算题卡** | 35% | "算出 ΔU" |
| **结果解释卡** | 10% | "P < 0.05 说明什么？" |

如果全出计算题，会漏掉**最容易失分的那一类**：方法选错，算得再对也是零分。

### 18.13 作答界面：只做数字 + 单位，不做公式编辑器

- 输入框：**数值** + **单位**（下拉常用单位 + 可自由输入）
- 不做 LaTeX 输入、不做符号演算
- 理由：兽医计算题八成是"套公式 + 换单位"，不是符号推导；做公式编辑器是给自己挖三个月坑

### 18.14 没有答案的题怎么办（最常见的情况）

同学手上经常只有题、没有答案。

1. 有答案的 → 直接入库
2. 没答案的 → AI 解答 + **sympy 验算** → 标「AI 解答·待确认」→ **你点一次确认**才进复习队列
3. 验算不通过 → 丢弃，不猜

和"AI 出题进待审队列"是同一条原则：**没确认的答案绝不当标准答案。**

### 18.15 成本现实

284 页纯计算课，入库成本约为同页数概念课的 **3–5 倍**。压成本只有两条路：
- 公式**区域裁切**而不是整页（已定）
- **LaTeX 结果按 hash 缓存复用**（同一个公式全库只转一次）

好消息：计算题本身几乎不增加成本，因为它来自例题/真题 + 程序化变式，不靠 AI 现编。

### 19.2 三个新发现

**① 课件是双语的，而且前后不一致**

标题是「描述性统计 / Descriptive Statistics」，但**前 4 章英文占比 34–54%，后 5 章只有 11–25%**——同一门课，早期英文版、后期中文版。同学两届混用，共享资料时会同时拿到两种。

**② `Review.pdf` 就是考纲，比任何 AI 推断都准**

老师亲自写的 22 页期末复习提纲，逐章逐点列：

```
2. Descriptive Statistics
• 基本术语 Some basic terminology
  1. 变量与观测值
  2. 总体与样本
  3. 参数与统计量
• 描述性统计 Descriptive statistics
  1. 统计图
  2. 描述性统计量：平均水平 / 离散程度
```

**这不是"提示"，这是考点树本身。** 应该直接导入成 `knowledge_point` 列表，再让 PPT 去给这些考点挂卡——而不是让 AI 从 552 页里猜考点。

**③ 统计符号在文本层被降级成了标点**

`HW3-Answer` 的原文是 `𝐻"：𝜇# = 𝜇$ = 𝜇% = 𝜇& = 𝜇'`，实际含义是 `H₀: μ₁ = μ₂ = μ₃ = μ₄ = μ₅`。

下标被映射成了 ASCII 偏移：`"`=0、`#`=1、`$`=2、`%`=3、`&`=4、`'`=5、`(`=6、`,`=7、`-`=8。

→ 结论和化学课一致但更严重：**统计符号必须走「裁切图 + VLM 转 LaTeX」，文本层不可信**。这个偏移规律可以拿来当"检测到公式"的信号，但不能靠它还原语义。

### 19.3 语言策略：双语，不做纯英文

- **正面**：中文术语为主，英文小字副标（`总体均值 / Population Mean`）
- **背面**：中文释义 + **保留老师英文原句**（考场认词靠原句）
- 题干：保留原文语言，下面加一行中文翻译

理由：考试可能中英混出，双语最稳；而且"认得出英文术语"本身是个考点。

### 19.4 复习提纲 → 直接当考点树（新增输入类型）

| 输入 | 产出 |
|---|---|
| **复习提纲 / 考纲**（`Review.pdf`） | **`knowledge_point` 列表（考点树）**，最高权重 S |
| 讲义 | 卡片，挂到已有考点下 |
| 作业 / 测验 / 练习 | 题目（带答案的最优质） |

这补上了之前"三类输入"里缺的一类：**考纲是骨架，讲义是血肉**。顺序应该是先考纲、后讲义。

### 19.5 统计的图是"解释型"，不是"识别型"

| | 病理（识别型） | 统计（解释型） |
|---|---|---|
| 卡面 | 图 + 问"这是什么病变" | 图 + 问"这个分布说明了什么" |
| 考点 | 认出来 | **判断形状、选对图形、读结论** |
| 背面 | 物种/器官/病变/病因 | 该看哪里 + 什么形状意味着什么 + 常见误读 |

同是"图卡"，正面背面的结构完全不同，不能共用一套模板。

### 19.6 查表是**工具**，不是卡片

t 表、F 表、χ² 表——背表没有意义，会查才是能力。所以：

- 内置临界值表（本地数据，不用联网）
- 练习形式：给 α、df，问临界值；或给统计量和临界值，问结论
- **不要**做成"记住 F₀.₀₅(4,23)=2.80"这种卡

### 19.7 判分要看中间量，不能只看最终答案

化学题通常一个数；**统计题是一条链**：

```
SS_品种 2755.24 → df 4 → MS 688.81 → F 8.15 → F₀.₀₅(4,23)=2.80 → 拒绝 H₀
```

老师的答案就是这个格式（含 ANOVA 表）。所以判分要支持**多步字段**：

- 每个中间量单独判（数值 + 容差）
- 最后结论单独判（拒绝/不拒绝）
- 结论对但中间量错 → 判"错"，但提示"你的结论对了，MS 算错了"——这比只判对错有用得多

### 19.8 题库永远不够，所以参数化出题是必须的

585 页讲义 vs **11 页题目**（HW1/HW3/HW4/Exercise/Quiz2）。老师给的题极少。

统计恰恰最适合参数化：
> 生成 n 组随机数据（指定均值、方差、样本量）→ 算 SS/MS/F → 判结论

答案由程序算，零 AI、无限变式、答案必然正确。

### 19.9 顺带打个预防针：第三类原型是"生信 / 代码类"

你提到以后可能有生信课。那类课件会长得不一样：

| | 生信课 |
|---|---|
| 一页是什么 | 一条命令 + 一段流程 + 一张结果图 |
| 复习单位 | **流程步骤** + **命令参数** |
| 卡型 | 流程排序卡、命令填空卡（`bwa index -a ___`）、报错排查卡 |
| 判分 | **可执行**（跑一下看输出对不对），比人工判分更硬 |

这个以后再细化，但现在有一条现在就该记住：**代码类科目的判分可以真跑**，这比"输入答案对数字"更可靠。

### 19.10 待你确认

1. **这门课考试是英文卷、中文卷、还是混出？** 决定卡片主语言。
2. **考试允许查表吗？** 允许 → 内置表 + 查表练习；不允许 → 得背几个常用临界值。
3. **`Review.pdf` 这种复习提纲，其他课有吗？** 如果有，它是最高价值的输入，优先级应该排在 PPT 前面。

### 19.11 公式识别与渲染：已实测跑通，不需要装 TeX（10-19）

问题：能不能把化学/统计里的公式识别出来并"打出来"？需不需要装 LaTeX？

**三件事要分开回答**：

| 环节 | 需要什么 | 现状 |
|---|---|---|
| **输出 LaTeX 代码** | 什么都不需要 | LaTeX 只是纯文本，直接写字符串 |
| **渲染**（把 LaTeX 显示成公式） | **KaTeX / MathJax**（浏览器内，几百 KB） | 产品里用 KaTeX；**不需要 TeX Live**（那是几个 GB） |
| **识别**（从 PDF 读出公式） | PyMuPDF 裁切 + VLM 读图 | 已跑通，见下 |

**实测链路**（`_probe/crop_formula.py` → 读图 → `_probe/latex_render.py`）：

1. 自动检测公式区域：含数学字符 / 上下标 / 数学字体（Symbol、Cambria Math）的 span，按行聚合成块
2. 裁切放大（220 dpi），只送这一小块给 VLM
3. 读出 LaTeX，例如：

```latex
x_{\mathrm{B}}=\frac{n_{\mathrm{B}}}{n_{\mathrm{A}}+n_{\mathrm{B}}}
\approx\frac{n_{\mathrm{B}}}{n_{\mathrm{A}}}
=\frac{n_{\mathrm{B}}}{m_{\mathrm{A}}/M_{\mathrm{A}}}
=b_{\mathrm{B}}M_{\mathrm{A}}
```

4. **用 matplotlib 的 mathtext 渲染回图片**，肉眼比对原图——本机已装，不需要 TeX

结论：**你不需要给我装任何东西。** 现状已经能"读到 → 写出 → 渲染验证"。

**但识别有上限，必须有闸门**（复杂矩阵、多层根式、手写扫描件会错）。三道校验，从便宜到贵：

1. **语法闸门**：LaTeX 能否被解析（KaTeX/matplotlib 报错即丢弃）
2. **渲染对比**：把 LaTeX 渲染成图，与原裁切图做相似度比较，低于阈值进"待人工确认"
3. **数值验算**（最强的）：公式里的数字抽出来做算术核对。例：`40.6 − 3.1 = 37.5` 对得上才收

成本：化学约 142 处公式、统计约 200 处，每处一次小图调用；同一裁切图 hash 命中缓存则不重复调用。

## 二十、预置仓库与例题金标准（10-19 夜）

### 20.1 你对前面四个问题的回答

| 问题 | 你的回答 | 落地 |
|---|---|---|
| 分析化学部分 | 以后慢慢发，或等工具做出来自己建仓 | 不阻塞，留接口 |
| 考试用计算器 | **允许** | 题目可以用真实、难算的数，不必凑整数 |
| 有效数字 | 一般两位小数，**但看题目要求** | 见 20.2，不能写死 |
| 生物统计 | 已学完，发来是为了把工具基础打厚 | 预置成仓库，见 20.4 |
| 开源范围 | GitHub 上只放**白板工具**，课程仓库是私有资产 | 与 D1/D7 一致，见 20.5 |

### 20.2 有效数字：读题目要求，而不是写死两位（D69）

考题里会明确写"保留两位小数"或"保留三位有效数字"。所以：

- **有明确要求** → 严格按它判（考试就这么判，读漏要求本身就是失分点）
- **没写** → 默认两位小数，但**位数不对不判错，只提示**

schema：`answer.precision = {kind: fixed_decimal | sig_fig | unspecified, value: 2}`

理由：如果一律按两位判，遇到"保留三位有效数字"的题，你把对的答案判成错的；反之则会让你在考场上因为位数丢分却从没被提醒过。

### 20.3 例题 = 出题金标准（D70）

**识别**：成对的「例：」+「解：」结构（实测这门课有 13 处），解析时打 `is_example = true`。

**四层作用**（不只是"多收一道题"）：

1. **例题本身是已确认答案的题**（老师给的解，S+ 级）
2. **例题的结构是出题模板**：已知量 → 求解目标 → 分步 → 结论
3. **例题的数值风格是对标**：保留几位、带不带单位、数据规模多大
4. **模拟卷出题时优先仿照例题**，而不是让 AI 自由发挥

具体做法：从例题抽出

```
given    已知量（含单位）
find     求什么
steps    解题步骤（分步）
gives    给分点（有就记）
precision 保留位数
unit_style 单位写法
```

存成 `problem_template` 后，所有变式题都从它生成。

> **"金标准"不只是那一道题，是出题器。**

这也顺带解决了"程序化出题从哪来模板"的问题——模板不用编，直接从老师的例题里抽。

### 20.4 预置仓库：出厂自带若干学科仓库（D71）

概念：工具可以**自带若干已经建好的学科仓库**，而不是只能从空白开始。

| 版本 | 内容 |
|---|---|
| **你的个人版** | 白板 + 5 个预置仓库（免疫、药理、病理、无机分析化学、生物统计） |
| **发布版（GitHub）** | **白板 + 基础提示词**，不带任何课程仓库 |

格式草案：

```

  兽医学/

    药理学/      ...
    病理解剖学/  ...
  公共基础/

    生物统计/       ...
```

`manifest.json`：`id / name / profession / mode(concept|calc|mixed) / version / cards / points / created_at / checksum`

- 卡片 `origin = preset`（区别于 seed / ai / human）
- 你改过的 preset 卡自动变 `human`，**升级预设时不覆盖**
- 可装可卸，卸载不影响其他课程

### 20.5 "白板"和"满配"是同一个东西的两个状态

你说得对——GitHub 上那个是白板，你手上的是满配。这不需要两套产品，只需要**预置仓库这个可选项**：

```

  └─ 空壳：引擎 + 基础提示词 + 0 个仓库

  └─ 空壳 + presets/（5 个课程仓库，私有，不进 git）
```

正好和已经做好的事一致：`.gitignore` 里 `data/` 与 `_probe` 派生物早就排除了，仓库里从来没有课件内容。

### 20.6 一个必须先解决的问题：5 门课一起进排程会互相摊薄

这是你上一句话里藏着的坑。每日配额是**全局 15 张**，如果 5 门课同时在排程里，每门课每天只剩 3 张——**每门课都学得很浅**。

所以预置仓库要有状态字段：

| 状态 | 含义 | 是否进排程 |
|---|---|---|
| `active` | 正在学 | ✅ 参与每日取卡 |
| `archive` | 学完了 | ❌ 不取卡，只可检索 / 参考 |

## 二十一、多课程并行：配额按课程算，不按全局算（10-19 夜）

### 21.1 我上一节写错了

我写的是"每日配额是全局 15 张，5 门课一起会摊薄"，推论出要用 active/archive 状态来限制。

**你说的是：每门课各自 15 张（新 10 + 旧 5），5 门课都开就是各自都有 15 张。**

- **D72｜配额按课程计算**，`daily_new_max` / `daily_review_max` 是**每门课**的上限，不是全局。
- 之前那条"active / archive"的推论作废——不需要靠归档来控制配额了。

不过 `archive` 这个状态本身还有用（学完的课不想每天看到它），但它的含义从"控制配额"变成"收进抽屉"，见 21.5。

### 21.2 触发机制：什么情况今天才出题

你的规则拆成三态（**D73**）：

| 你的动作 | 含义 | 是否生成今天的队列 |
|---|---|---|
| **导入新 PPT / 新资料** | 今天学了新东西 | ✅ **自动生成 15 张**，不用再按按钮 |
| 点开这门课看看 | 只是查看，没学 | ❌ 不生成 |
| 点「开始今天的 15 张」 | 明确要学 | ✅ 生成 |

### 21.3 一个简化：把"开关"和"开始"合成同一个按钮

你描述的是"课程里有个按钮，表明今天是否出题"。我建议**不要再单独做一个开关**——因为"开始今天的 15 张"这个按钮，按下去本身就等于说"我今天学这门课"。

两个控件会带来一个必然的问题：你按了开关但没开始，或者开始了但忘了按开关，状态就对不上了。

所以只有一个按钮，三种入口：

```
进入课程 → 今天还没有队列
           └─ [ 开始今天的 15 张 ]    ← 按了就生成

进入课程 → 今天已有队列（导入过 / 或已开始）
           └─ [ 继续：已完成 7/15 ]
```

**导入新课件时自动进入"已生成"状态**，你打开就能直接刷。

### 21.4 首页形态要改（修正 §14.3）

我原来设计"首页只有一个按钮，今天 15 张"——那是**单课程模型**，在你这个多课程模型下不成立。

正确形态是：**左侧课程栏 + 右侧内容区**（桌面端的经典布局，也是你说的"一栏一栏"）。

```
┌──────────────┬───────────────────────────────────┐
│ 课程          │  免疫学                            │
│              │                                    │
│ ● 免疫学  15 │  今天 15 张  (新 10 · 旧 5)        │
│ ○ 药理学   – │  已学 7/15                         │
│ ○ 病理学   – │                                    │
│              │  [ 继续：还剩 8 张 ]               │
│ ─────────    │                                    │
│ + 导入        │  本章进度 ██████░░░░ 62%           │
│ 检索 · 设置    │                                    │
└──────────────┴───────────────────────────────────┘
```

- 左侧每行显示：课程名 + 今天还剩几张（`–` 表示今天没开始）
- `●` 表示今天已生成队列，`○` 表示还没
- 右侧只显示**当前课程**，不并列多课

### 21.5 一个真实的副作用：会不知不觉开到 5 门

5 门全开 = 75 张/天 ≈ 40 分钟。这本身不是错，但**你得知道自己开了多少**。

所以首页顶部常驻一行：

```
今天已排 2 门课 · 30 张 · 约 22 分钟
```

超过 3 门时，那行字变成提示色。**只提示，不阻止**——这是你的工具，不是监工。

`archive` 状态在这里仍有用：学完的课收进"已归档"分组，默认不显示在左侧列表里，但可以随时展开、随时手动刷。

### 21.6 跨课程的到期卡各自计算

每门课独立排队列，所以：

- 某门课三天没点开 → 它的到期卡堆着，但**不影响别的课**
- 再点开那天：到期卡可能 >5 张，按已有规则（D13）由旧卡补足、总量仍按 15 张；超出的按 D46 的"积压上限"处理（建议不超过 2 天量，超出砍低星）

### 21.7 schema 影响

- `daily_queue(course_id, date, ...)` —— **主键带 course_id**，不是全局一张表
- P-1 里的 `daily_new_max` / `daily_review_max` 是**每门课生效**的上限；如果需要"全局总上限"（防止 5 门全开），另加一个可选的 `global_daily_cap`，默认关闭
- `course.state`：`active` / `archived`（只影响左侧列表是否显示，不影响配额）

## 二十二、课程仓库：给人看的那个入口（10-19 夜）

### 22.1 需求

每门课除了"今天 15 张"，还要有一个**能翻的仓库**：

> 我今天不想刷 15 张，只想背题——那就点开整门课的仓库，
> 看到老师整理好的全部知识点（各种专有名词），
> 点开一个名词 → 详细释义 + 配图。

这正是你最早说的那句"**仓库要给人和机器一起看，但是要分开**"里，**给人看的那一套**终于有了界面。

### 22.2 课程页变成两个入口

```
┌──────────────┬───────────────────────────────────┐
│ 课程          │  免疫学                            │
│              │  ┌────────┬────────┐              │
│ ● 免疫学  15 │  │  今天   │  仓库   │              │
│ ○ 药理学   – │  └────────┴────────┘              │
│              │                                    │
│ ─────────    │  ▼ 第 3 章 免疫应答        214 项   │
│ + 导入        │      3.1 抗原提呈           18 项  │
│ 检索 · 设置   │      3.2 T 细胞活化         26 项  │
│              │  ▶ 第 4 章 免疫系统        180 项  │
└──────────────┴───────────────────────────────────┘
```

- **今天**：只有队列（开始 / 继续 / 结算）
- **仓库**：整门课的目录，纯浏览，不进排程、不消耗配额

### 22.3 浏览器的三种视图

| 视图 | 排序 | 什么时候用 |
|---|---|---|
| **章节目录**（默认） | 章 → 小节 → 考点/术语 | 通读、复习整章 |
| **索引** | 拼音 / 英文字母 | 快速找一个词（配 `Ctrl+K` 检索） |
| **按重要度** | 星级从高到低 | 考前只过重点 |

### 22.4 点开一个术语，右侧出详情

```
抗原提呈                            ★★★★☆  掌握 62%
────────────────────────────────────────────
APC 摄取抗原并在 MHC 分子上呈递给 T 细胞的过程。

[ 机制图 ]  （可点击放大、可翻页看下一步）

⚠ 易错：抗原提呈（过程）≠ 抗原提呈细胞（实体）
特性 / 子项：见 5 项 ›
出处：第4章 p12   [ 查看原文 ]

你：最近 3 次 · 模糊 2 次 · 距今 6 天
[ 加入今天的队列 ]   [ 就这一张，考我 ]
```

最后那两个按钮是关键：**从浏览里随时能把某个点拉进今天的队列，或者立刻单张自测**。这样"我今天只想背几个"就真的能成立，不必被 15 张绑定。

### 22.5 我的三个补充（你没提，但缺了会变味）

**① 释义默认折叠，点词名才展开**

列表只显示术语名（像书的索引）。你先看到"补体三条途径"，心里过一遍，再点开对答案。

这样**浏览本身就成了低强度复习**。如果一上来把释义全铺开，翻完三百条你什么也没记住。

**② 顶部加一个筛选器：只看薄弱的 / 只看高星 / 只看没考过的**

考前最有用的是"只看我还没记住的"。没有这个筛选，仓库就是个漂亮的 PDF。

**③ 浏览页要能"标记"**

看到重要的点，点一下 ⭐ 进"待复习"清单。否则就是收藏夹陷阱：**翻了 200 条，一条也没进脑子**。

### 22.6 能导出（给自己用）

- 导出整门课为 **Markdown + 图片**（就是你最初说的"给人看的那套仓库"）
- 导出 PDF 便于打印

⚠️ 默认只导到自己本地。**不做"一键发给同学"**——课程数据属于私有资产（D1/D7），分享的是工具不是数据。

### 22.7 一个必须防的退化

浏览视图最大的风险不是做不出来，而是**做完之后没人用它复习**——因为浏览很轻松，复习很难，人一定选轻松的那个。

所以这个页面的定位要写清楚：

> **仓库是"查"和"过"的地方，不是"学"的地方。**
> 学还是得回到队列里，因为那里才判对错、才算间隔。

界面上也要暗示这一点：浏览页不显示"今天已完成"之类的进度，避免让人觉得"翻了就算学过了"。

**② 名言不能瞎编**

## 二十四、开工前的最后一批设计（10-19 深夜）

### 24.1 卡片编辑器（D74）

**卡片的构成**：专有名词 → 注释 → 配图（可有可无）→ 相关概念（关系）。

复习时右上角有「修改」按钮（和「释义有误」「图配错」并排），点开：

```
编辑：槟榔肝
─────────────────────────────
词条    [ 槟榔肝            ]
注释    [ 肝小叶中央区淤血伴周边脂肪变性…  ]
配图    [ 替换 ] [ 删除 ] [ 添加 ]
        ┌──────────┐
        │  缩略图   │
        └──────────┘
相关概念
  ↑ 先修/上溯：肝淤血          [ 改 ]
  ↔ 并列/辨析：肝脂变          [ 改 ]
  ↓ 导致/下溯：（空）          [ + 添加 ]
─────────────────────────────
[ 保存 ]  [ 取消 ]  [ 恢复 AI 原版 ]
```

要点：
- 改过的字段标 `origin=human`，可一键恢复 AI 原版
- **关系也能改**：先后（先修/导致）、并列（同层对比）两类，改错了可修
- 保存后立刻影响卡背显示与检索，不需要重建批次

### 24.2 卡背的"相关概念"：可点击跳转（D74-2）

### 24.3 术语别名管理：采用 SKOS 式"首选词 + 别名"（D75）

查了业界做法，词表领域的共识非常统一（[ANSI/NISO Z39.19](https://www.niso.org/publications/ansiniso-z3919-2005-r2010)、[SKOS](https://www.w3.org/TR/skos-reference/)、SNOMED CT、UMLS）：

> **一个概念只有一个"首选词"（preferred term），其他都是"别名"（alternative / variant term）。别名不产生新概念。**

落到本项目：

```
concept（概念）  1 ─── n  term（词形）
                            kind: preferred | alt | hidden | misspelling
                            origin: ppt | human | ai
```

五条规则：
1. 一个概念只能有**一个**首选词（显示、检索排序用它）
2. 别名**不产生新卡**，只影响检索和去重
3. **合并** = 把概念 B 的所有词形移到 A，B 变成"重定向"（保留来源，不丢历史）
4. **拆分** = 从 A 移出若干词形，新建概念（原来的来源文献跟着走）
5. **重定向要能撤销**——这是关键，合错了必须能拆回来

人工/AI 分工：AI 提议"这两个可能是同一个词"（带证据：同页共现、定义相似），**人工确认**才合并。这与"AI 提议 + 人工确认"的一贯原则一致。

界面上只需要三个动作：**合并 / 拆分 / 改首选词**。不要做复杂的词表编辑器。

### 24.4 关系与依赖图：可点击的交互图（D76）

你的想法我明白了，而且比"看图"强得多：

- **不是 PPT 里那张图**，而是 AI 读相邻几页后**生成的交互图**
- 图里的每个专有名词**可点击**，直接跳到那个概念的卡
- 边的方向表示因果/先后，边也有类型（上溯 / 下推 / 并列）

技术形态：**SVG 画布**（不是图片），节点是 DOM 元素，天然可点、可悬停、可拖拽。

```
        ┌──────────┐
        │  肝淤血   │
        └────┬─────┘
             │ 导致
        ┌────▼─────┐        ┌──────────┐
        │  槟榔肝   │◄──并列──│  肝脂变   │
        └────┬─────┘        └──────────┘
             │ 进展
        ┌────▼─────┐
        │  肝硬化   │
        └──────────┘
```

- 点节点 → 右侧抽屉打开该术语详情（不离开图）
- 悬停 → 高亮它的所有边
- 生成方式：**AI 从相邻页提议关系**（哪些词常同页出现、哪些是"导致/引起/表现为"），人工可改（见 24.1）
- 图是"视图"，不是"内容"：所有节点都是库里已有的概念 id，图本身不存文字

### 24.11 平台定稿：Electron 桌面端（10-19 深夜，修订 D81）

你问"网页版是不是临时的"，答案是：**界面代码不是临时的，外壳是临时的。现在外壳也换成桌面了。**

| | 之前 | 现在 |
|---|---|---|
| 外壳 | 浏览器打开 `127.0.0.1:5173` | **Electron 窗口**（无地址栏、无端口） |
| 数据通道 | 本地 HTTP + fetch | **IPC**（`window.nativeApi.invoke`），不起端口 |
| 前端代码 | HTML/CSS/JS | **完全一样，一行没改**（只把 `/app.js` 改成 `./app.js`，并加了一条 IPC 分支） |
| 分发 | 需要装 Node | 便携版 exe，双击即用 |

为什么前端不用重写：Electron 内部就是一个 Chromium，桌面程序跑的就是这套 HTML/CSS/JS。**"网页技术"和"网页"是两件事。**

**已产出**：`build/课到卡/课到卡.exe`（388 MB，Electron 正常体积），整个文件夹拷走就是绿色版。

**打包方式**：`electron-builder` 卡在下载依赖（GitHub 被墙），所以改成手工打包——复制 Electron 运行时 + 把 `package.json / app / tools` 放进 `resources/app`。效果等同，只是暂时没有安装向导和自定义图标。

**一个必须承认的缺口**：现在导出 PDF 仍要调用系统的 Python（解析器是 Python + PyMuPDF）。**同学的电脑上没有 Python 就导入不了。** 下一步要把解析器也打进 exe（PyInstaller 打包成单个 exe，或改用 JS 解析库）。

### 24.12 配图：从课件原图抠，不让 AI 画（10-19 深夜）

**已实现**（`tools/ingest.py` 的 `extract_page_images`）：

| 规则 | 值 | 作用 |
|---|---|---|
| 图片面积占整页比例 | ≥ 4% | 滤掉校徽、页眉图标 |
| 最短边 | ≥ 120 px | 滤掉装饰线、小标 |
| 归属 | 该页面积最大的图 → 该页产出的卡 | 一页一张主图 |

实测：205 张卡里 **39 张有配图**（19%）。剩下 81% 的页本来就没有图（纯文字页）。
抽出来的确实是内容图——病理那批是 HE 染色的组织切片，不是校徽。

展示：卡背与术语详情都能看图，点一下放大（最小版图片查看器，完整版见 §24.7）。

**关于"AI 手绘"：不做，而且建议别做。**

理由不是成本，是**错得危险**：

- 形态学图片（组织切片、病变外观）AI 生成的是"看起来很像但细节错误"的图。学生记错一个结构，考试要扣分，临床上要出事。
- 课件原图 = 老师的考试口径，本身就是最可信来源。
- 以后要"生成图"，只用于**示意性的机制图**（SVG 交互图，§24.4 已定），不做写实病理图。

下一步可以做的（比 AI 画图有用得多）：
1. **图注结构化**：病理那种"物种，器官，病变，病因"的图注，一条自动派生三张卡（§18.4 / D32）
2. **按术语位置裁切**：同一页多图时，按术语所在区域挑对应的那张
3. **一卡多图**（当前只存一张）

### 关于"AI 画图"结论的修订

§二十四说"不做 AI 生成图"，当时的语境是**形态学写实图**（切片、病变外观），这个结论仍然有效。

现在的机制图是**从已有概念和关系里排布出的示意图**，不生成任何写实内容，不涉及"编造病理形态"，因此不受那条限制。

边界仍然清楚：
- 可以做：流程、通路、因果链、分类树（信息已经在课件里）
- 不做：组织切片、病变大体照、任何"看起来像真的"的写实图
